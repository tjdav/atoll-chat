# Dynamic OpenAPI Router Test Verification Report

## 1. Current Test Structure
Inspection of `server/tests/openapi_generation.rs` reveals four test functions:
- `test_openapi_doc_validity`: Validates serde round-tripping, metadata (title "Atoll Encrypted Chat API", version "3.0.4"), bearer security scheme, multipart request bodies, observer stream content type, secret validation notes, ciphertext/signature binary formats, OPRF rotate warnings, and hardcoded path assertions. It contains a hardcoded array `expected_paths` of exactly **68 path items**.
- `test_openapi_cli_subcommand_out_flag`: Validates `server openapi generate --out <path>` creates a valid JSON file matching `ApiDoc::openapi()`.
- `test_openapi_cli_default_invocation`: Validates default output to `docs/openapi.json`.
- `test_router_and_openapi_paths_match_one_to_one`: Asserts specific paths (`/sockudo/auth`, `/health`, `/ready`, `/api/v1/oprf/blind`, `/api/v1/admin/rooms/{id}/sessions`) and contains a regex/substring scanner over `include_str!("../src/lib.rs")`. However, its final loop only checked `for openapi_path in &openapi_paths { assert!(router_paths.contains(openapi_path)); }`, which verified that OpenAPI paths existed in the router (subset check), but did NOT assert that all router paths were documented in OpenAPI (superset check).

## 2. Router Introspection Feasibility
- **Axum Version**: Axum `0.8` (with `features = ["multipart"]`) as declared in `server/Cargo.toml`.
- **Introspection Capability**: Axum `0.8` `Router` does not expose public introspection methods to enumerate registered routes programmatically at runtime.
- **Feasibility Assessment**: Approach (a) — parsing `server/src/lib.rs` source via `include_str!("../src/lib.rs")` at test time — is fully feasible and robust. `server/src/lib.rs` declares all HTTP routes using explicit `.route("<path>", ...)` and `.nest("<prefix>", ...)` calls.

## 3. Path Prefix Handling
In `server/src/lib.rs`:
- `api_routes` (`let api_routes = Router::new()...`) contains 114 `.route(...)` declarations.
- `app` (`let mut app = Router::new()...`) contains 6 `.route(...)` declarations (`/health`, `/ready`, `/sockudo/auth`, and 3 model serving endpoints `/models/...` when hosting is enabled).
- `app` mounts `api_routes` via `.nest("/api/v1", api_routes)`.
- The parser extracts `.route(...)` paths within the `api_routes` block and prepends `/api/v1`. Routes defined directly on `app` are kept at their root path.

## 4. Known Path Transformations & Normalization
- Trailing slashes are normalized by stripping trailing `/` (except root `/`).
- Path parameters (`{id}`, `{bot_id}`, `{session_id}`, `{item_id}`, `{key}`, etc.) are matched literally as string tokens between router definitions and OpenAPI specifications.
- Exact string equivalence after `.nest("/api/v1", ...)` prefix application is used for exact set comparison.

## 5. OpenAPI Path Extraction
- Options:
  a. Read `docs/openapi.json` from disk.
  b. Call `ApiDoc::openapi()` directly in memory.
- Assessment: Option (b) `ApiDoc::openapi()` is more robust as it tests the actual in-memory `utoipa` OpenAPI schema generated by current code without requiring prior execution of the file generation subcommand or disk I/O.
