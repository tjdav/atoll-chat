# Overview

### JavaScript engine

The prebuilt PocketBase executable comes with an embedded ES5 JavaScript engine ([goja](https://github.com/dop251/goja)) which enables you to write custom server-side code using plain JavaScript.

You can start by creating `*.pb.js` file(s) inside a `pb_hooks` directory next to your executable.

```javascript
// pb_hooks/main.pb.js

routerAdd("GET", "/hello/{name}", (e) => {
    let name = e.request.pathValue("name")

    return e.json(200, { "message": "Hello " + name })
})

onRecordAfterUpdateSuccess((e) => {
    console.log("user updated...", e.record.get("email"))

    e.next()
}, "users")
```

_For convenience, when making changes to the files inside `pb_hooks`, the process will automatically restart/reload itself (currently supported only on UNIX based platforms). The `*.pb.js` files are loaded per their filename sort order._

For most parts, the JavaScript APIs are derived from `Go` with 2 main differences:

*   Go exported method and field names are converted to camelCase, for example:  
    `app.FindRecordById("example", "RECORD_ID")` becomes `$app.findRecordById("example", "RECORD_ID")`.
*   Errors are thrown as regular JavaScript exceptions and not returned as Go values.

##### Global objects

Below is a list with some of the commonly used global objects that are accessible from everywhere:

*   `__hooks` - The absolute path to the app `pb_hooks` directory.
*   `$app` - The current running PocketBase application instance.
*   `$apis.*` - API routing helpers and middlewares.
*   `$os.*` - OS level primitives (deleting directories, executing shell commands, etc.).
*   `$security.*` - Low level helpers for creating and parsing JWTs, random string generation, AES encryption, etc.
*   And many more - for all exposed APIs, please refer to the `JSVM reference docs`.

### TypeScript declarations and code completion

While you can't use directly TypeScript (_without transpiling it to JS on your own_), PocketBase comes with builtin **ambient TypeScript declarations** that can help providing information and documentation about the available global variables, methods and arguments, code completion, etc. as long as your editor has TypeScript LSP support.

The types declarations are stored in `pb_data/types.d.ts` file. You can point to those declarations using the [reference triple-slash directive](https://www.typescriptlang.org/docs/handbook/triple-slash-directives.html#-reference-path-) at the top of your JS file:

```javascript
/// <reference path="../pb_data/types.d.ts" />

onBootstrap((e) => {
    e.next()

    console.log("App initialized!")
})
```

If after referencing the types your editor still doesn't perform linting, then you can try to rename your file to have `.pb.ts` extension.

### Caveats and limitations

##### Handlers scope

Each handler function (hook, route, middleware, etc.) is **serialized and executed in its own isolated context as a separate "program"**. This means that you don't have access to custom variables and functions declared outside of the handler scope. For example, the below code will fail:

```javascript
const name = "test"

onBootstrap((e) => {
    e.next()

    console.log(name) // <-- name will be undefined inside the handler
})
```

The above serialization and isolation context is also the reason why error stack trace line numbers may not be accurate.

One possible workaround for sharing/reusing code across different handlers could be to move and export the reusable code portion as local module and load it with `require()` inside the handler but keep in mind that the loaded modules use a shared registry and mutations should be avoided when possible to prevent concurrency issues:

```javascript
onBootstrap((e) => {
    e.next()

    const config = require(`${__hooks}/config.js`)
    console.log(config.name)
})
```

##### Relative paths

Relative file paths are relative to the current working directory (CWD) and not to the `pb_hooks`.  
To get an absolute path to the `pb_hooks` directory you can use the global `__hooks` variable.

##### Loading modules

Please note that the embedded JavaScript engine is not a Node.js or browser environment, meaning that modules that rely on APIs like _window_, _fs_, _fetch_, _buffer_ or any other runtime specific API not part of the ES5 spec may not work!

You can load modules either by specifying their local filesystem path or by using their name, which will automatically search in:

*   the current working directory (_affects also relative paths_)
*   any `node_modules` directory
*   any parent `node_modules` directory

Currently only CommonJS (CJS) modules are supported and can be loaded with `const x = require(...)`.  
ECMAScript modules (ESM) can be loaded by first precompiling and transforming your dependencies with a bundler like [rollup](https://rollupjs.org/), [webpack](https://webpack.js.org/), [browserify](https://browserify.org/), etc.

##### Engine limitations

We inherit some of the limitations and caveats of the embedded JavaScript engine ([goja](https://github.com/dop251/goja)):

*   Has most of ES6 functionality already implemented but it is not fully spec compliant yet.
*   No concurrent execution inside a single handler (aka. no `setTimeout`/`setInterval`).
*   Wrapped Go structural types (such as maps, slices) come with some peculiarities and do not behave the exact same way as native ECMAScript values.
*   In relation to the above, DB `json` field values require the use of `get()` and `set()` helpers.

# Event hooks

You can extend the default PocketBase behavior with custom server-side code using the exposed JavaScript app event hooks.

Throwing an error or not calling `e.next()` inside a handler function stops the hook execution chain.

All hook handler functions share the same `function(e){}` signature and expect the user to call `e.next()` if they want to proceed with the execution chain.

### App hooks

**onBootstrap**
Triggered when initializing the main application resources (db, app settings, etc). Note that attempting to access the database before the `e.next()` call will result in an error.
```javascript
onBootstrap((e) => {
    e.next()
    // e.app
})
```

**onSettingsReload**
Triggered every time when the `$app.settings()` is being replaced with a new state.
```javascript
onSettingsReload((e) => {
    e.next()
    // e.app.settings()
})
```

**onTerminate**
Triggered when the app is in the process of being terminated (ex. on `SIGTERM` signal).
```javascript
onTerminate((e) => {
    // e.app
    // e.isRestart
})
```

### Mailer hooks

**onMailerSend**
Triggered every time when a new email is being sent using the `$app.newMailClient()` instance.
```javascript
onMailerSend((e) => {
    e.message.subject = "new subject"
    e.next()
})
```

**onMailerRecordPasswordResetSend**
Triggered when sending a password reset email to an auth record.
```javascript
onMailerRecordPasswordResetSend((e) => {
    // e.app, e.mailer, e.message, e.record, e.meta.token
    e.next()
})
```

### Realtime hooks

**onRealtimeConnectRequest**
Triggered when establishing the SSE client connection.
```javascript
onRealtimeConnectRequest((e) => {
    // e.app, e.client, e.idleTimeout, and all RequestEvent fields...
    e.next()
})
```

### Record model hooks

Lower level Record model hooks triggered from anywhere (custom console command, scheduled cron job, when calling `e.save(record)`, etc.). They have no access to the request context!

**onRecordEnrich**
Triggered every time when a record is enriched (builtin Record responses, realtime message serialization, or when `apis.enrichRecord` is invoked).
```javascript
onRecordEnrich((e) => {
    e.record.hide("role")
    e.next()
}, "posts")
```

**onRecordAfterCreateSuccess**
Triggered after each successful Record DB create persistence. Delayed until AFTER transaction commit.
```javascript
onRecordAfterCreateSuccess((e) => {
    // e.app, e.record
    e.next()
}, "users")
```

**onRecordAfterUpdateSuccess**
Triggered after each successful Record DB update persistence.
```javascript
onRecordAfterUpdateSuccess((e) => {
    // e.app, e.record
    e.next()
}, "users")
```

**onRecordAfterDeleteSuccess**
Triggered after each successful Record DB delete persistence.
```javascript
onRecordAfterDeleteSuccess((e) => {
    // e.app, e.record
    e.next()
}, "users")
```

### Request hooks

Triggered only when the corresponding API request endpoint is accessed.

**onRecordsListRequest**
```javascript
onRecordsListRequest((e) => {
    // e.app, e.collection, e.records, e.result
    e.next()
})
```

**onRecordViewRequest**
```javascript
onRecordViewRequest((e) => {
    // e.app, e.collection, e.record
    e.next()
})
```

**onRecordCreateRequest**
```javascript
onRecordCreateRequest((e) => {
    // e.app, e.collection, e.record
    e.next()
})
```

**onRecordUpdateRequest**
```javascript
onRecordUpdateRequest((e) => {
    // e.app, e.collection, e.record
    e.next()
})
```

**onRecordDeleteRequest**
```javascript
onRecordDeleteRequest((e) => {
    // e.app, e.collection, e.record
    e.next()
})
```

**onRecordAuthRequest**
Triggered on successful API record authentication (sign-in, token refresh, etc.).
```javascript
onRecordAuthRequest((e) => {
    // e.app, e.record, e.token, e.meta, e.authMethod
    e.next()
})
```

# Routing

Register custom routes and middlewares using the top-level `routerAdd()` and `routerUse()` functions.

### Routes

```javascript
// register "GET /hello/{name}" route
routerAdd("GET", "/hello/{name}", (e) => {
    let name = e.request.pathValue("name")
    return e.json(200, { "message": "Hello " + name })
})

// register "POST /api/myapp/settings" route (authenticated only)
routerAdd("POST", "/api/myapp/settings", (e) => {
    return e.json(200, {"success": true})
}, $apis.requireAuth())
```

##### Path parameters and matching rules

Route paths follow `net/http.ServeMux` syntax:
- `{paramName}` - matches a single segment.
- `{paramName...}` - matches multiple segments.
- `{$}` - matches the end of the URL.

Examples:
- `routerAdd("GET", "/static/{path...}", ...)`
- `routerAdd("GET", "/customers/{name}", ...)`

##### Retrieving the current auth state

```javascript
let authRecord = e.auth
let isGuest = !e.auth
let isSuperuser = e.hasSuperuserAuth()

// Or via requestInfo (useful in hooks)
let info = e.requestInfo()
let record = info.auth
```

##### Reading request data

```javascript
// Path parameters
let id = e.request.pathValue("id")

// Query parameters
let search = e.request.url.query().get("search")

// Headers
let token = e.request.header.get("Some-Header")

// Body
let body = e.requestInfo().body
console.log(body.title)

// Typed Body binding
const data = new DynamicModel({
    title: "",
    age: 0,
})
e.bindBody(data)
```

##### Writing response data

```javascript
e.json(200, {"name": "John"})
e.string(200, "Hello")
e.html(200, "<h1>Hello</h1>")
e.redirect(307, "https://example.com")
e.noContent(204)
e.fileFS($os.dirFS("..."), "example.txt")
```

### Middlewares

```javascript
routerUse((e) => {
    if (e.request.header.get("Something") == "") {
        throw new BadRequestError("Missing header")
    }
    return e.next()
})
```

Builtin middlewares:
- `$apis.requireGuestOnly()`
- `$apis.requireAuth(optCollectionNames...)`
- `$apis.requireSuperuserAuth()`
- `$apis.requireSuperuserOrOwnerAuth(ownerIdParam)`
- `$apis.bodyLimit(limitBytes)`
- `$apis.gzip()`
- `$apis.skipSuccessActivityLog()`

# Database

`$app.db()` returns a `dbx.Builder` for running SQL statements.

### Executing queries

```javascript
// Execute (non-select)
$app.db().newQuery("DELETE FROM articles WHERE status = 'archived'").execute()

// One row
const result = new DynamicModel({ id: "", status: false })
$app.db().newQuery("SELECT id, status FROM users WHERE id=1").one(result)

// All rows
const results = arrayOf(new DynamicModel({ id: "", status: false }))
$app.db().newQuery("SELECT id, status FROM users LIMIT 100").all(results)
```

### Binding parameters

Use `{:paramName}` placeholders to prevent SQL injection.
```javascript
$app.db()
    .newQuery("SELECT name FROM posts WHERE created >= {:from}")
    .bind({ "from": "2023-06-25 00:00:00.000Z" })
    .all(result)
```

### Query builder

```javascript
const result = arrayOf(new DynamicModel({ id: "", email: "" }))

$app.db()
    .select("id", "email")
    .from("users")
    .andWhere($dbx.like("email", "example.com"))
    .limit(100)
    .orderBy("created ASC")
    .all(result)
```

Available `dbx.Expression` methods:
- `$dbx.exp(raw, params)`
- `$dbx.hashExp({ col: val })`
- `$dbx.not(exp)`
- `$dbx.and(...exps)`, `$dbx.or(...exps)`
- `$dbx.in(col, ...vals)`, `$dbx.notIn(col, ...vals)`
- `$dbx.like(col, ...vals)`, `$dbx.notLike(col, ...vals)`
- `$dbx.between(col, from, to)`
- `$dbx.exists(subquery)`

### Transaction

Use `$app.runInTransaction(fn)` to execute multiple queries in a transaction.
```javascript
$app.runInTransaction((txApp) => {
    const record = txApp.findRecordById("articles", "RECORD_ID")
    record.set("status", "active")
    txApp.save(record)
})
```

# Record operations

### Set and Get field values

```javascript
record.set("title", "example")
record.set("users+", "6jyr1y02438et52") // append to relation
record.load({ title: "new", active: true })

record.get("title")
record.getBool("active")
record.getInt("age")
record.getStringSlice("tags")
record.expandedOne("author")
record.expandedAll("categories")
```

### Auth accessors

```javascript
record.isSuperuser()
record.email()
record.setEmail("test@example.com")
record.setVerified(true)
record.validatePassword("123456")
record.setPassword("new-password")
```

### Fetch records

```javascript
// Single record (throws if not found)
let record = $app.findRecordById("articles", "RECORD_ID")
let record = $app.findFirstRecordByData("articles", "slug", "test")

// Multiple records
let records = $app.findRecordsByIds("articles", ["ID1", "ID2"])
let total = $app.countRecords("articles", $dbx.hashExp({status: "pending"}))
let records = $app.findRecordsByFilter(
    "articles",
    "status = 'public' && category = {:category}",
    "-published",
    10, 0,
    { category: "news" }
)

// Auth records
let user = $app.findAuthRecordByEmail("users", "test@example.com")
let user = $app.findAuthRecordByToken("TOKEN", "auth")
```

### Create and Update record

```javascript
// Create
let collection = $app.findCollectionByNameOrId("articles")
let record = new Record(collection)
record.set("title", "Hello")
$app.save(record)

// Update
let record = $app.findRecordById("articles", "RECORD_ID")
record.set("title", "Updated")
$app.save(record) // use saveNoValidate(record) to skip validation

// Files
let file = $filesystem.fileFromPath("/path/to/file.txt")
record.set("document", file)
record.set("images+", [file1, file2]) // append
record.set("images-", ["old_file.png"]) // remove
```

### Expanding relations

```javascript
$app.expandRecord(record, ["author", "categories"], null)
console.log(record.expandedOne("author"))
```

### Tokens

```javascript
let token = record.newAuthToken()
let token = record.newVerificationToken()
let token = record.newPasswordResetToken()
let token = record.newFileToken()
```

# Migrations

Migrations are located in `pb_migrations` and executed in a transaction on `serve` or `migrate up`.

### Creating migrations

```bash
./pocketbase migrate create "my_migration"
```

```javascript
// pb_migrations/12345_my_migration.js
migrate((app) => {
    // up
    app.db().newQuery("UPDATE ...").execute()
}, (app) => {
    // down (optional)
})
```

### Examples

**Initialize settings**
```javascript
migrate((app) => {
    let settings = app.settings()
    settings.meta.appName = "My App"
    app.save(settings)
})
```

**Create superuser**
```javascript
migrate((app) => {
    let superusers = app.findCollectionByNameOrId("_superusers")
    let record = new Record(superusers)
    record.set("email", "admin@example.com")
    record.set("password", "password123")
    app.save(record)
})
```

# Jobs scheduling

Set up crontab-like jobs with `cronAdd(id, expr, handler)`.

```javascript
// prints "Hello!" every 2 minutes

})
```

Remove a job: `cronRemove("id")`.

# Rendering templates

PocketBase provides `$template` for parsing and rendering HTML templates.

```javascript
const html = $template.loadFiles(
    `${__hooks}/views/layout.html`,
    `${__hooks}/views/hello.html`,
).render({ "name": "John" })
```

**Template syntax (Go templates)**:
- `{{ .name }}` - renders a variable.
- `{{ block "name" . }}...{{ end }}` - defines a block.
- `{{ define "name" }}...{{ end }}` - overrides a block.
- `{{ .content | raw }}` - renders unescaped content.

# Sending HTTP requests

Use `$http.send(config)` for external API calls.

```javascript
const res = $http.send({
    url:     "https://example.com/api",
    method:  "GET",
    headers: { "Content-Type": "application/json" },
    timeout: 120,
})

console.log(res.statusCode)
console.log(res.json) // parsed JSON
```

**Multipart/form-data**
```javascript
const formData = new FormData();
formData.append("title", "Hello")
formData.append("file", $filesystem.fileFromBytes("content", "test.txt"))

const res = $http.send({
    url: "...",
    method: "POST",
    body: formData,
})
```

# Realtime messaging

Send custom realtime messages via `$app.subscriptionsBroker()`.

```javascript
const message = new SubscriptionMessage({
    name: "my_topic",
    data: JSON.stringify({ hello: "world" }),
});

const clients = $app.subscriptionsBroker().clients()
for (let id in clients) {
    if (clients[id].hasSubscription("my_topic")) {
        clients[id].send(message)
    }
}
```

Client-side:
```javascript
pb.realtime.subscribe('my_topic', (e) => {
    console.log(e.data)
})
```

# Filesystem

Access the storage abstraction via `$app.newFilesystem()`.

### Reading files

```javascript
let record = $app.findAuthRecordByEmail("users", "test@example.com")
let key = record.baseFilesPath() + "/" + record.get("avatar")

let fsys = $app.newFilesystem();
let reader = fsys.getReader(key)
let content = toString(reader)
reader.close()
fsys.close()
```

### Saving and Deleting

Handled automatically via `record.set()` and `$app.save()`.
Manual usage:
- `fsys.upload(content, key)`
- `fsys.delete(key)`
